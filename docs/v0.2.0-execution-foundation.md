# WulfPeak v0.2.0 execution foundation

This implementation slice establishes the contracts needed before analysis
steps are enabled. It deliberately stops after full preflight and command-plan
generation.

## Included

- run-level `paired_end` and `single_end` models
- strict exact SE and PE FASTQ discovery
- path-safe sample and group identifiers
- group-level peak type, numeric q-value, and control consistency
- normalized run configuration and CLI validation
- complete Bowtie2 `.bt2` or `.bt2l` family checks
- PATH-based external tool detection and best-effort version capture
- shell-free command execution support
- deterministic SE/PE command plans
- atomic stdout destinations for commands whose output is an artifact
- explicit temporary, validator, canonical, and promotion fields per artifact
- complete strict-majority consensus plans with supporting sample IDs
- schema-2 manifest and run metadata
- atomic JSON, TSV, and status writes
- `null`, `running`, `done`, and `failed` state models
- conservative signature/output-aware resume predicate
- non-blocking advisory output-directory lock
- read-only human and JSON status output
- standalone output-manifest validation entry point

## Deferred by design

FastQC, trimming, alignment, BAM processing, coverage, peak/group processing,
and reporting commands are represented in `command_plan.json` but are not
executed. Calling `run` without `--dry-run` fails clearly and does not create a
successful pipeline status. Later implementation PRs attach real step
executors and validators to this foundation.

## Dry-run invariants

Preflight resolves and validates every sample before an analysis command could
start. A successful dry-run records tool provenance and warnings, creates no
analysis output, creates no sample/group `done` marker, and leaves
`pipeline.status` at `null` for a new output directory. Existing `done` and
`failed` state is never reset by dry-run.

## Command-plan contract

`command_plan.json` schema 2 represents work as ordered step `actions`.
External command actions store an argument array and an optional `stdout_path`;
stdout artifacts are written through a sibling temporary file and atomically
replaced only when the command exits successfully. Pipelines explicitly require
every child return code to succeed. Internal normalization and summary actions
are named operations with declared inputs and temporary outputs.

Every final artifact declares:

- `temporary_path`, owned by its step
- a type-specific `validator`
- `canonical_path`
- `promotion: validate_then_atomic_file_replace`

An executor must run the validator against the temporary artifact and may call
`os.replace` only after validation succeeds. Promotion retains the canonical
parent directory and replaces only the declared file, so an existing non-empty
FastQC or MACS3 directory is safe on forced rerun. Partial or invalid artifacts
never replace a canonical output. Directory artifacts are rejected by the plan
schema.

The consensus step plans BED sorting and within-replicate BED3 merging,
`bedtools multiinter` with sample names, strict-majority filtering using
`floor(n / 2) + 1`, support TSV generation, and final adjacent-segment merging.
