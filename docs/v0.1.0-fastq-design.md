# WulfPeak v0.1.0 samplesheet and FASTQ design

## Resolution flow

1. Parse `samples.tsv` as a strict six-column TSV.
2. Validate all row-local constraints, uniqueness, and control references.
3. For each `input_id`, construct the finite set of supported R1 and R2 names.
4. Compare those names with regular files immediately inside `--fastq-dir`.
5. Require exactly one candidate for each mate; never rank candidates.
6. Derive canonical trimmed paths from `sample_id` and `--output-dir`.
7. Write metadata only after every sample resolves.

FASTQ discovery is isolated in
`wulfpeak.fastq.discover_fastq_pair(input_id, fastq_dir)`. It returns a
`FastqPair` or raises one of three actionable errors:

- `FastqNotFoundError` when neither mate exists (or the directory is invalid)
- `FastqPairMismatchError` when exactly one mate exists
- `AmbiguousFastqError` when either mate has multiple candidates; the message
  lists every R1 and R2 candidate found

`input_id` has no pattern semantics. Discovery compares complete filename
strings, and does not recurse or follow an `input_id` into a subdirectory.

## Manifest as the downstream interface

`config/manifest.json` is the source of truth for workflow paths. Each sample
record contains its six samplesheet values plus:

```json
{
  "raw_fastq": {
    "r1": "/absolute/path/to/input_R1_001.fastq.gz",
    "r2": "/absolute/path/to/input_R2_001.fastq.gz"
  },
  "trimmed_fastq": {
    "r1": "/analysis/WulfPeak_out/trimmed/sample_R1_val_1.fq.gz",
    "r2": "/analysis/WulfPeak_out/trimmed/sample_R2_val_2.fq.gz"
  }
}
```

Trim Galore integration must capture its two outputs and normalize them to the
declared `trimmed_fastq` paths by rename or symlink. Alignment and every later
step consume these manifest paths rather than reconstructing names.
